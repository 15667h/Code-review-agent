## 三、本地运行

```bash
cd backend
pip install -r requirements-dev.txt        # 只有 httpx + pytest

# 可选：配真实模型（不配则跑离线规则模式，界面会明说）
cp .env.example .env
#   LLM_BASE_URL=https://api.deepseek.com
#   LLM_API_KEY=sk-...
#   LLM_MODEL=deepseek-chat

python -m harness.server --port 8765
# 打开 http://127.0.0.1:8765/
```

**登录**：首次启动会自动创建测试账号，登录页有「测试账号」一键进入按钮
（`demo@margin.dev` / `Margin-demo-2026`）。

**注意**：用 `file://` 双击 `index.html` 不会显示任何样例数据 —— 界面会明确提示
「后端没连上」并给出启动命令。这是有意设计：一份「看起来跑完了」的结果，
比一句「没连上」更容易让人误判系统能力。

## 四、三分钟上手路径

1. 打开工作台，**左侧轨道切到「代码审查」** —— 侧栏自动只显示可审查的仓库（12 个靶场）
2. 任选一个仓库，在输入坞里写审查重点（或直接回车用默认目标）
3. 观察中间区域：**计划 → 工具调用 → 发现列表**，每一步都可展开看真实输出
4. 运行结束后看底部的**运行统计**（轮数 / 耗时 / 结束原因 / token / 缓存命中率），点「查看完整报告」
5. **切到「架构设计」** —— 侧栏变成空的（案例代码不入库），运行
   `bash backend/arch-cases/fetch-cases.sh` 拉取上游后重试
6. 架构运行结束后，看**证据核验面板**：可精确定位率、ok/weak/bad 分布、分类型明细，
   以及每个组件/决策下面可复制的「代码依据」路径

## 五、想验证「它说的是真的」

本项目把「可核验」当成产品的一部分。下面几条命令可以自己验证：

```bash
cd backend

# 1. 回归测试（282 项，约 13 秒）
python -m pytest -q

# 2. 死代码与未用导入（应当 0 可疑项）
python scripts/check_hygiene.py

# 3. 报告里的数字是现算的，不是手抄的
python -m eval.make_report         # 审查侧
python -m eval.make_arch_report    # 架构侧（需要 arch-cases 的原始结果）

# 4. 密钥边界
git check-ignore -v backend/.env
```

**引用任何数字前请先读那两份报告的「已知局限」一节** —— 那里写清了样本规模、
口径、波动范围与失效条件。这个项目刻意记录了「哪些结论不能下」。
