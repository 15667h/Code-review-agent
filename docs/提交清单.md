## 二、提交前自检

### 2.1 敏感信息（赛题硬性要求：API 密钥不得出现在公开仓库）

```bash
# 这三条都应当命中的是「被忽略」，而不是被跟踪
git check-ignore -v backend/.env          # 期望：.gitignore:41:.env
git check-ignore -v backend/.auth/        # 期望：.gitignore:71:backend/.auth/
git check-ignore -v backend/.runs/        # 期望：.gitignore:16:backend/.runs/

# 远程树里不应出现敏感文件（期望输出 0）
git ls-tree -r origin/main --name-only | grep -cE '(^|/)\.env$|backend/\.auth/|backend/\.runs/'
```

- [ ] 仓库里只有 `.env.example`，没有 `.env`
- [ ] `backend/.auth/`（账号表，含密码哈希）未入库
- [ ] `backend/.runs/`（运行归档，可能含被审代码片段）未入库
- [ ] `backend/arch-cases/*/repo/`（上游克隆）未入库

### 2.2 可运行性（评审者拿到仓库后应当能跑起来）

```bash
cd backend
pip install -r requirements.txt
python -m harness.server --port 8000
# 浏览器打开 http://127.0.0.1:8000/
```

- [ ] 不配置 API Key 也能启动（离线规则模式）
- [ ] 登录页可用测试账号一键进入（`demo@margin.dev` / `Margin-demo-2026`）
- [ ] 界面上能看到两个助手（代码审查 / 架构设计）

### 2.3 测试与评估

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest -q          # 期望：175 passed
```

- [ ] 回归测试全绿
- [ ] `backend/BENCHMARK.md` 中的数字与 `eval/` 下原始结果一致（由脚本生成，不手抄）

### 2.4 文档完整性

- [x] README 的「团队信息」已填写（组别、学校、成员、指导教师、联系方式）
- [x] 技术文档 PDF 的封面团队信息已填写

- [ ] 技术文档包含「AI 技术说明」（第 4 章）与「创新点说明」（第 7 章）
