## 二、提交前自检

```bash

git check-ignore -v backend/.env          # 期望：.gitignore:47:.env
git check-ignore -v backend/.auth/        # 期望：backend/.auth/
git check-ignore -v backend/.runs/        # 期望：backend/.runs/

# 远程树里不应出现敏感文件（期望输出 0）
git ls-tree -r origin/main --name-only | grep -cE '(^|/)\.env$|backend/\.auth/|backend/\.runs/'
```

- [ ] 仓库里只有 `.env.example`，没有 `.env`
- [ ] `backend/.auth/`（账号表，含密码哈希）未入库
- [ ] `backend/.runs/`（运行归档，可能含被审代码片段）未入库
- [ ] `backend/arch-cases/*/repo/`（上游克隆）未入库

### 2.2 可运行性（评审者拿到仓库后应当能跑起来）

```bash
cd backend
pip install -r requirements.txt
python -m harness.server --port 8000
# 浏览器打开 http://127.0.0.1:8000/
```

- [ ] 不配置 API Key 也能启动（离线规则模式，界面会明说未配置）
- [ ] 登录页可用测试账号一键进入（`demo@margin.dev` / `Margin-demo-2026`）
- [ ] 界面上能看到两个助手（代码审查 / 架构设计）
- [ ] 配置中心只需填三项（接口地址 / API Key / 模型名）即可用真实模型

## 四、数据与隐私说明

- 被审代码只在本机处理，服务默认仅绑定 `127.0.0.1`；
- API Key 通过环境变量注入，不写入任何提交文件；配置中心只回显首尾各 4 位；
- 账号密码以 scrypt 加盐哈希存储在本机 `.auth/`，不入库；
- 运行归档落在本机 `.runs/`，不入库（已知不足：归档未做凭据脱敏，见技术文档 8.2）。
