# 多语言支持 · 实现说明

> 2026-10-25 实现。**编程语言**支持（不是自然语言）。四个 Agent 全部生效，
> 且**新增 Agent 自动继承**。零新增依赖。

---

## 一、先说清楚支持到什么程度

项目定位是零依赖（唯一外部依赖 `httpx`），所以没有 tree-sitter。
这意味着**不可能对所有语言做同等的结构分析**。诚实的做法是分级：

| 级别 | 语言 | 能做什么 |
|---|---|---|
| **deep**（完整 AST） | **Python** | 符号图、跨文件调用（`who_calls`/`impact`）、测试覆盖（`tests_for`）、精确符号与签名 |
| **shallow**（词法级） | JavaScript、TypeScript、Java、Go、Rust、Ruby、PHP、C#、Kotlin、Swift、C、C++、Scala、**Lua** | 规则扫描（硬编码密钥、危险反序列化、命令注入、弱哈希、调试残留、eval 类）；`read_symbols` 给启发式定义清单 |
| **text** | 其他一切 | 只能 `read_file` / `grep` |

**共 15 种语言**，29 个扩展名。

### 为什么必须分级而不是「统一支持」

如果假装 JS 和 Python 一样支持，会出现这类错误：
在 JS 仓库调 `who_calls` 返回空 → 模型理解成「没人调用」→ 得出「可以随便改」的结论。
**那是错误的事实，而错误的事实在报告里看起来和正确的一样。**

## 二、核心设计：一处声明，全局生效

### `harness/languages.py`（新增，唯一事实来源）

```python
LANGUAGES = {
    "python":     Language(id="python", level=DEEP, suffixes=(".py", ".pyi"), ...),
    "typescript": Language(id="typescript", level=SHALLOW, ...),
    ...
}
```

所有模块都从这里取，不再各写一份：

| 模块 | 之前 | 现在 |
|---|---|---|
| `rules.py` | `suffixes = (".py",)` 硬编码 | 从 `languages` 按语言反查 |
| `rules.scan_tree` | 只扫 `.py` | 扫**所有已注册语言** |
| `codegraph.py` | `PY_SUFFIX = ".py"` | 结构图仍只 Python，但**清点全部语言** |
| `tools_common.read_symbols` | 非 `.py` 直接拒绝 | 浅层符号提取 |
| 测试文件识别 | `test_*.py` | 委托给 `languages.is_test_file`（覆盖 8 种命名约定） |
| 离线模型 | `pattern="*.py"` | `pattern="*"` + `_is_source_file` 过滤 |

### 新增 Agent 自动继承：`loop.py` 统一注入

```python
# run_agent 里
system_prompt = f"{spec.system_prompt.rstrip()}\n\n{prompt_section()}"
```

`prompt_section()` 生成「语言能力」段落（774 字符），拼进**每个** Agent 的 system prompt。
写新 Agent 时**不需要在 prompt 里写任何语言相关的话**。

**为什么放在静态前缀而不是每轮消息**：
① 它是稳定文本（只随代码版本变），进前缀不破坏 KV 缓存；
② 放进每轮消息会让缓存前缀每轮失效，长运行的输入成本翻倍。

## 三、四个 Agent 各自怎么用

| Agent | 语言支持体现 |
|---|---|
| `review` | 规则扫描覆盖 15 种语言（6 条规则跨语言）；`build_graph` 返回语言清点 |
| `architect` | `sketch` / `list_files` 按语言发现文件；`read_symbols` 对 JS/Go 给浅层清单 |
| `tester` | `check_coverage` 分两段：Python 精确 / 其他语言启发式（**分开统计，口径不同不能混**） |
| `planner` | `impact` 在 Python 上可用；浅层语言会明确说明「调用关系需人工核对」 |

所有 Agent 的 prompt 里都有同一条硬约束：

> **不要把「查不到」说成「不存在」。** 在浅层语言上调 who_calls / impact 会返回空结果，
> 那只说明「本工具在这个语言上做不了」，**不说明没有调用方**。

## 四、新增的跨语言规则

原有 10 条规则里 2 条可跨语言（SEC001 硬编码密钥、SEC003 eval），
新增 4 条，共 **6 条跨 15 种语言**：

| ID | 规则 | 为什么能跨语言 |
|---|---|---|
| SEC001 | 硬编码密钥 | 各语言的赋值语法都覆盖得到（见下） |
| SEC003 | 动态执行 | `eval` / `exec` / `new Function` / `vm.runIn*` / `setTimeout("...")` |
| SEC004 | 危险反序列化 | `pickle` / `yaml.load` / `unserialize` / `ObjectInputStream` |
| SEC005 | 命令注入 | `os.system` / `shell=True` / `child_process.exec` / `exec("...$")` |
| SEC006 | 弱哈希 | `md5` / `sha1` / `createHash('md5')` |
| QUAL001 | 调试残留 | `console.log` / `fmt.Println` / `System.out.println` / `println!` |

其余 8 条（裸 `except`、可变默认参数、`open` 无 `with` 等）是 Python 语法专属 ——
**强行跨语言只会误报**，所以明确只作用于 Python。

## 五、实测踩到的四个 bug

### bug 1：`scan_tree` 默认只扫 `.py`，混合仓库静默失明

改完 `scan_tree` 后我跑了混合语言仓库，**只报 Python 的命中**，TS/Go 的硬编码密钥一条没报，
而输出看起来是「扫完了、没问题」。

**更严重的是它差点没被发现**：我第一次的字符串替换**静默失败**了
（文档字符串不匹配，`s.replace` 没匹配上就直接返回原文）。
代码看起来"改过了"，实际没变。后来加了 `assert old in s` 才抓住。

> 教训：改代码用字符串替换时**必须断言匹配成功**。
> 静默失败的表现和「成功」一模一样，只有跑测试才看得出来。

### bug 2：`_iter_lines` 只认后缀不认语言 id

传 `language="typescript"` 时静默退回 `#` 前缀，导致 TS 的
`// function commented() {}` 被当成真实函数定义报出来。

修：先查 `LANGUAGES.get(language)`，再退回按后缀查。

### bug 3：`//` 与 Python 地板除冲突

一套通用注释剥离逻辑会让 `total = a // b + c` 变成 `total = a`，
后半段的规则检测全部失效。修：**按语言给注释前缀**，单字符前缀走原状态机。

多字符前缀还有个坑：`const u = "http://x" // c` 里的 `//` 在字符串内，
不能当注释 —— 所以先扫描字符串边界。

### bug 4：Java/C# 的修饰词不是函数关键字

`func_keywords` 里放 `"private "` 会导致
`private String name = "x";` 被报成函数。修：只留 `void `，
其余靠「行以 `{` 结尾」判方法形态（字段以 `;` 结尾，天然排除）。

### bug 5：离线模型硬编码 `pattern="*.py"`

离线 review 在混合仓库只检查 Python 文件。修：`pattern="*"` + `_is_source_file` 过滤。

## 八、怎么新增一种语言

只改 `harness/languages.py` 一处：

```python
_add(Language(
    id="dart",
    display="Dart",
    suffixes=(".dart",),
    level=LEVEL_SHALLOW,
    line_comment=("//",),
    block_comment=(("/*", "*/"),),
    test_patterns=(r"_test\.dart$",),
    func_keywords=("void ",),
    class_keywords=("class ", "mixin ", "enum "),
    string_delims=('"', "'"),
    limits="无 AST：不支持符号图、跨文件调用追踪、测试覆盖分析。",
))
```

之后自动获得：
- 规则扫描（6 条跨语言规则自动生效）
- `read_symbols` 浅层提取
- 测试文件识别
- `build_graph` 语言清点
- 所有 Agent 的 prompt 里出现 Dart

**不需要改任何 Agent 代码，也不需要改任何工具代码。**

## 九、已知边界（如实说明）

1. **非 Python 没有符号图**。`who_calls` / `impact` / `tests_for` 只对 Python 有结果。
   工具返回里会明确说明，prompt 里也要求模型不要把空结果说成「不存在」。
2. **浅层符号提取是启发式**。字符串/多行模板里的关键字可能误认，匿名函数与装饰器包裹会漏，
   拿不到签名。返回里标注了「不是 AST」。
3. **规则在浅层语言上误报率更高**（只能靠正则）。所以 `QUAL001` / `SEC006` 定级是 `note`，
   不是 `blocker` —— 静态看不出它是否用于安全场景。
4. **不引 tree-sitter**。这会破坏零依赖定位。若以后需要真正的多语言 AST，
   建议做成**可选后端**（装上就用，没装降级到现状），而不是硬依赖。
